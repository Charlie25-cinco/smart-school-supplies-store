## Conventions

POS validation-error pages use natural height rather than the fitted panel constraint, preserving visible correction fields and submission in short windows. Keep that recovery behavior in responsive checks. Payment inputs must remain outside .checkout-scroll; only basket lines occupy that region. Native order details remain inside checkout-form even while the dialog is closed.

- Store money as integer centavos. Validate decimal input before parsing it; never trust browser prices or totals.
- Checkout, reservations, payment, and stock movements use database transactions. Available stock is stock minus reserved. Conditional writes prevent overselling; unique checkout references and normalized GCash references prevent duplicate recording.
- Confirmed unpaid orders reserve products. Payment deducts stock/releases reservations once and creates a sale from frozen order prices. Cancelled unpaid orders release reservations once; dispatched goods must be confirmed returned. Paid cancellations/refunds are outside scope. Completed fulfillment requires payment.
- Order editing is restricted to preparing/ready. Financial edits require unpaid status; paid customer corrections preserve sale/receipt amounts. Compare a server-derived SHA-256 token covering current details, status/payment and item snapshots inside the transaction. Retained lines keep frozen prices; added lines use active inventory prices. Increase/decrease reservations by the quantity difference and roll back all changes on failure. Deactivated retained items can be kept/reduced, but cannot be newly added or increased. No internal supplies in an order.
- Services do not automatically consume stock. Internal supplies use kind=consumable, are excluded from POS, and support owner-recorded usage with actor/reason. Usage cannot consume reserved stock. Item kind is immutable; old order/receipt snapshots never change after product edits.
- Admin manages inventory/accounts and views all orders/sales read-only; Cashiers transact on their own records. Guard routes and service mutations, not only navigation. Guest/inactive/unknown-role access is forbidden. Order receipts remain attributed to the creator; paid_by records the collecting Cashier. No public registration/default credentials; preserve historical collectors after upgrade.
- Bootstrap Admin privately with `php artisan store:staff --role=admin` (legacy owner alias supported); Admin manages Cashiers in the UI. Hash passwords through Laravel, never flash/log them, and invalidate sessions on reset/disable. Secrets remain in ignored `.env`; no secrets in catalog configuration.
- Database and runtime files remain ignored. Never commit database files, real staff data, transaction data, logs, or screenshots of sensitive content.
- The documented demo reset uses `php artisan migrate:fresh --seed` followed by `php artisan store:staff --role=admin`; it removes accounts, sales, and inventory edits. Approval to document these commands does not authorize executing a reset. Never verify reset documentation against the actual store database; use read-only command/source checks or an isolated test database.
- Laravel is served from `public/`; static catalog deployment uses only `catalog/`. The public catalog has manually maintained data and cannot access local stock.
- Use Asia/Manila for store dates. Sample prices/stock must remain clearly labeled until replaced with real data.
- Apply the current 0.6.0 design described in ARCHITECTURE.md: strong navy surfaces, yellow checkout accents, warm-white catalog cards, and separate green/amber/red semantic statuses. Inter lives in catalog/assets/fonts with its OFL license; Vite bundles that same asset for staff use. Do not add remote font requests. Keep visible focus, labels, semantic headings, responsive layouts, and deliberate empty/error states. Stock-dialog context is derived on the server; failed validation restores only that dialog and its inputs.
